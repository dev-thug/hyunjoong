카카오페이증권이 기술로 투자의 장벽을 허물어왔듯, 저는 AI Agent 기술로 개발과 운영의 복잡함을 자동화하고 싶습니다. 지난 4년간 스타트업에서 풀스택 엔지니어이자 테크 리더로서, 대규모 트래픽 처리를 위한 서버리스 아키텍처를 설계하고 AI를 실제 비즈니스 로직에 내재화하는 데 집중해왔습니다.

특히 최근 개인 프로젝트인 Specify.app을 통해 단순한 LLM 연동을 넘어, GraphRAG 기반의 지식 검색과 Multi-Agent 오케스트레이션을 구현하며 '환각 없는 정확한 AI'와 '실행 가능한 자동화'를 실험하고 있습니다. 이러한 경험을 바탕으로 카카오페이증권 DevOps팀의 Internal Platform에 AI를 심어, SDLC(소프트웨어 개발 생명주기) 전반을 가속화하는 동료가 되고 싶습니다.

1. Specify.app: GraphRAG와 Multi-Agent로 완성한 AI 협업 도구

DevOps팀이 목표로 하는 'SDLC 전반의 AI 적용'을 위해서는 단순한 텍스트 생성을 넘어, 문맥을 정확히 이해하고 복잡한 작업을 스스로 수행하는 Agent가 필수적입니다. 저는 협업 문서 편집 플랫폼 Specify.app을 개발하며 이 문제를 기술적 아키텍처로 풀어냈습니다.

[AWS Neptune & Bedrock 기반 GraphRAG 도입] 기존 RAG 방식이 가진 '파편화된 정보 검색의 한계'를 극복하기 위해, 현재 Amazon Neptune(Graph DB)과 Bedrock을 결합한 GraphRAG 아키텍처를 적용하고 있습니다. 문서 내의 키워드뿐만 아니라 문서 간의 위계와 연결 관계(Edge)를 지식 그래프(Knowledge Graph)로 모델링했습니다. 이를 통해 AI가 "A 프로젝트의 배포 설정 파일 찾아줘"라는 모호한 요청을 받았을 때도, 그래프상의 연관 노드를 탐색하여 정확한 문맥을 파악하고 환각(Hallucination)을 획기적으로 줄였습니다. 이는 금융 도메인의 복잡한 규제 문서나 인프라 간 의존성을 파악해야 하는 Internal Platform 구축에 즉시 적용 가능한 기술입니다.

2. 유전체 분석 플랫폼: 대규모 데이터 파이프라인과 운영 안정성

AI 모델이 성능을 발휘하려면 안정적인 데이터 파이프라인이 뒷받침되어야 합니다. 저는 유전체 분석 스타트업에서 1,000개 이상의 샘플 데이터를 동시에 처리하는 대규모 파이프라인을 구축하고 운영했습니다.

AWS Batch 기반 병렬 처리: 기존의 순차 처리 방식을 AWS Batch와 Docker 컨테이너 기반의 병렬 아키텍처로 전환하여, 분석 시간을 30분에서 10분으로 단축했습니다. 이 과정에서 Spot Instance 활용 전략을 도입해 월 인프라 비용을 92% 절감하는 성과를 거뒀습니다.

Event-Driven 아키텍처: EventBridge와 SQS를 활용해 데이터 수집부터 전처리, 분석, 결과 저장까지의 흐름을 비동기로 연결했습니다. 이는 AI 학습 데이터 파이프라인(수집-전처리-학습-서빙) 구축에 필요한 아키텍처 역량과 맞닿아 있습니다.

3. Human-in-the-loop: 금융 환경에 적합한 안전한 자동화

금융 서비스에서의 AI 도입은 '속도'만큼이나 '안전'과 '통제'가 중요합니다. 저는 Specify.app과 이전 의료 데이터 프로젝트(Fortuna Helix)에서 Human-in-the-loop(인간 개입) 프로세스를 설계의 핵심으로 두었습니다.

AI가 코드를 생성하거나 배포 스크립트를 작성하더라도, 최종 실행 권한은 인간에게 부여하는 승인 절차를 시스템화했습니다. 또한, 의료 데이터 처리 시 ISO 27001 인증 심사에 대응하며 데이터 격리(Multi-tenancy)와 감사 로그 시스템을 구축한 경험이 있습니다. 이러한 경험은 카카오페이증권의 Internal Platform이 금융 컴플라이언스를 준수하면서도, 개발자에게는 유연한 자동화를 제공하는 데 기여할 것입니다.
