클라우드 풀스택 엔지니어

김현중

엘리스는 교육 플랫폼을 넘어, 자체 구축한 AI 데이터센터와 클라우드 플랫폼을 기반으로 공공·기업 전반의 AI 전환을 실제로 가능하게 만드는 회사라고 생각합니다. 최신 GPU와 국산 NPU, 보안 인증을 갖춘 인프라 위에서 AI 인프라–플랫폼–모델–콘텐츠를 하나의 생태계로 연결하고 있다는 점이 인상 깊었습니다. 특히 엘리스 클라우드팀이 단순 VM 제공을 넘어서, 클러스터 관리·사용량 기반 과금·AI 학습 환경까지 책임지는 구조를 만든다는 점에서 제가 해온 Cloud·Client·Server 풀스택 개발 경험과 정확히 맞닿아 있다고 느꼈습니다.

저는 지난 4년간 스타트업에서 대규모 연산 작업과 실시간 요청이 공존하는 시스템을 설계·운영해왔습니다. 유전체 분석 플랫폼에서는 단일 EC2 기반 구조를 서버리스·이벤트 드리븐 아키텍처로 전환해, 처리 시간을 30분에서 10분으로 줄이고 월 인프라 비용을 약 92% 절감했습니다. 이 경험을 통해 "컴퓨팅 자원을 어떻게 배치하고 회수하느냐"가 곧 제품 경쟁력이라는 것을 체감했습니다. 이는 GPU 사용량이 빠르게 증가하는 엘리스 클라우드에서 성능·비용·안정성을 동시에 개선하는 데 직접적으로 활용할 수 있는 경험이라고 생각합니다.

리소스 관리·과금·인증 흐름을 풀스택 관점에서 개선해, 사용자가 GPU 인프라를 더 직관적으로 활용할 수 있는 경험을 만드는 데 기여하고 싶습니다. 단기적인 기능 구현에 그치지 않고, 운영 가능한 구조와 팀이 공유할 수 있는 기준과 개발문화를 함께 만들어가겠습니다.

1. 대규모 컴퓨팅 자원을 코드로 제어, 비용과 성능 개선

유전체 분석 플랫폼에서는 1,000개 이상의 샘플을 동시에 처리하는 장시간 배치 작업과 사용자 실시간 요청이 함께 존재했습니다. 초기 단일 서버 구조는 트래픽 변화에 취약했고, 비용도 고정적으로 증가하는 문제가 있었습니다. 저는 AWS Batch를 활용한 병렬 처리 구조와 SQS/EventBridge 기반 이벤트 분리를 통해 작업 흐름을 재설계했습니다. 참조 데이터는 EFS로 공유하되, 병목 구간을 모니터링하며 배치 단위와 동시성을 조정했습니다.

  • 병렬 처리 아키텍처 설계: AWS Batch를 활용해 1,000개 이상의 샘플을 동시에 처리하는 병렬 컴퓨팅 시스템을 구축했습니다. EFS를 활용한 대용량 참조 데이터(10GB) 공유 최적화와 병렬 처리 확장 시 발생한 I/O 스로틀링 문제를 CloudWatch로 관측하고 개선안을 수립했습니다.
  • 이벤트 기반 비동기 분리: EventBridge와 SNS/SQS를 활용한 이벤트 기반 비동기 분리 구조를 구현했습니다. "실시간 요청/상태"와 "장기 배치 작업"을 분리해 안정성을 확보했고, DLQ와 재시도 로직을 포함한 운영 구조를 함께 설계했습니다.
  • 사용량 기반 자원 관리: 단일 EC2 구조를 AWS Batch 기반 서버리스 아키텍처로 전환해, 작업량에 맞춰 리소스를 탄력적으로 사용하도록 구성했습니다. 사용하지 않을 때는 자원이 자동으로 회수되어 비용이 발생하지 않도록 설계했습니다.

그 결과 처리 시간은 30분에서 10분으로 단축(66% 개선)되었고, 사용량 기반으로 자원이 할당·회수되는 구조를 만들어 월 인프라 비용을 약 92% 절감할 수 있었습니다. 또한 재시도 로직과 DLQ, 알림을 포함한 운영 구조를 함께 설계해, 장애 상황에서도 서비스가 멈추지 않도록 했습니다. 이 경험은 엘리스 클라우드의 VM/컨테이너 기반 인프라와 연동되는 백엔드 서비스를 안정적으로 운영하는 데 그대로 연결될 수 있다고 생각합니다.

2. 빠른 실험과 학습을 통한 기술 확장

개인 프로젝트 Specify.app에서는 AI를 보조 기능이 아닌 사용 흐름의 중심에 둔 협업 문서 편집 AI Agent를 개발했습니다. 문서 작성 중 발생하는 문맥을 AI가 이해하고, 요약·정리·형식화·초안 생성을 자연스럽게 이어주는 구조를 목표로 설계했습니다.

  • 실시간 협업 아키텍처: 실시간 협업은 Y.js(CRDT)기반으로 구현했으며, 편집 상태 합의는 클라이언트에서 처리하고 서버는 상태 브로드캐스트·권한 관리·저장에 집중하는 구조로 분리했습니다. 이를 통해 다수 사용자의 동시 편집 환경에서도 충돌 없이 안정적인 동기화를 유지했고, 실시간 상태 전파는 AppSync Subscription으로 구성했습니다.
  • 서버리스 백엔드 설계: 백엔드는 AWS Lambda(TypeScript) 기반 서버리스 구조로 구현했으며, AI 기능은 Bedrock 기반 에이전트 호출을 이벤트 단위로 분리해 비동기 처리했습니다. 모델 호출은 지연과 실패를 전제로 설계해 타임아웃·재시도·중복 실행 방지를 적용했고, 결과는 문서에 직접 반영하지 않고 사용자 선택이 가능한 제안/초안 형태로 제공했습니다.
  • 비용 및 성능 최적화: CRDT 문서 전체를 전달하는 대신, 변경된 diff와 커서 주변 컨텍스트, 문서 메타데이터만 전달하도록 입력을 최소화해 호출 비용과 응답 시간을 제어했습니다. 이를 통해 실시간 협업 환경에서도 AI 기능을 안정적으로 결합한 풀스택 서비스를 완성했습니다.

이 프로젝트에서의 경험은 엘리스 개발팀이 추구하는 "빠른 실험과 학습을 통한 기술 확장" 철학과 일치합니다. 새로운 기술을 도입할 때 단순히 기능을 추가하는 것이 아니라, 사용자 경험과 시스템 안정성을 함께 고려하며 점진적으로 개선하는 방식을 실천했습니다.

3. 측정 가능한 근거와 공유로 팀의 속도를 높이는 협업 방식

저는 문제를 개인 역량으로 해결하기보다, 측정 가능한 근거와 설계 의사결정을 공유하며 팀의 속도를 높이는 방식으로 일해왔습니다. 테크 리드로서도 "내가 맞다"보다는 로그·지표·실험 결과를 문서로 정리해 팀이 함께 판단할 수 있도록 했습니다. 이러한 방식은 엘리스가 지향하는 수평적 커뮤니케이션과 잘 맞는다고 생각합니다.

  • 관측 가능성 기반 의사결정: CloudWatch 기반 로그/메트릭 수집 및 알림 체계를 구축해, 장애 원인 추적 시간을 단축하고 데이터 기반 의사결정을 가능하게 했습니다. EFS 트래픽 모니터링을 통해 병목 구간을 식별하고, 다중 EFS 분산/로드밸런싱 개선안을 수립했습니다.
  • 문서화와 지식 공유: 인프라 변경과 아키텍처 결정을 문서로 정리하고, 팀 내 코드 리뷰 세션을 통해 성능 최적화와 안정성 개선 방향을 함께 논의했습니다. 단순한 코드 지적이 아니라, 성능 개선 방향과 대안을 함께 제안하는 방식으로 피드백을 진행했습니다.
  • 오너십 기반 프로젝트 리딩: 사이드 프로젝트부터 실무 서비스까지 아이디어 단계부터 운영까지 직접 책임져온 경험 덕분에, 오너십 기반으로 프로젝트를 리딩하는 문화에도 익숙합니다. 합류 후에는 제가 만든 구조와 개선 사항을 개인 노하우로 남기지 않고, 문서와 공유 세션을 통해 팀의 자산으로 축적하겠습니다.

엘리스의 가치인 Growth·Diversity·Impact는 제게 "새 기술을 빠르게 흡수해 실제 사용자 경험과 숫자를 바꾸는 것"입니다. 엘리스 클라우드팀에서 인프라와 소프트웨어를 함께 다루며, AI 시대에 사람들이 더 빠르고 쉽게 가치를 만들 수 있는 기반을 만드는 엔지니어로 성장하고 싶습니다.
