Fullstack Product Engineer, AI Agent

김현중

오늘의집 AI Agent 팀에 합류해 인테리어 의사결정을 탐색에서 상담으로 바꾸는 제품 전환을, 풀스택으로 끝까지 책임지고 싶습니다. 오늘의집 AI Agent 팀이 목표로 하는 것은 단순 챗봇이 아니라, 사용자가 인테리어 의사결정을 "검색"이 아닌 "상담"으로 해결하도록 만드는 제품 구조의 전환이라고 이해했습니다. 저는 지난 4년간 스타트업에서 문제 정의부터 설계, 구현, 운영 안정화, 지표·비용 개선까지 end-to-end로 책임지며, 시스템과 제품을 동시에 바꿔온 풀스택 엔지니어입니다.

1. AI Agent를 '기능'이 아닌 '제품의 중심 흐름'으로 만든 경험

저의 강점은 역할 경계를 나누지 않고, 사용자 경험과 시스템 안정성을 함께 설계해 실서비스 결과로 증명해온 점입니다. React/Next.js 기반 UI부터 API 설계(REST/GraphQL), 데이터 모델링(DynamoDB), 인증/권한(Cognito), 배치·이벤트 처리(AWS Batch, SQS, EventBridge)까지 직접 설계·구현·운영한 풀스택 구현 역량을 보유하고 있습니다. 특히 개인 프로젝트 Specify.app을 통해 "AI를 기능으로 붙이는 것"이 아니라, AI가 사용자의 작업 흐름 자체를 바꾸는 경험을 설계하고 구현했습니다. 사용자가 막연한 요구를 대화로 구체화하고, 문맥을 유지한 채 문서를 발전시키는 AI 편집 파트너를 만들면서 'AI를 동료처럼 쓰는 개발 방식'이 제게 가장 자연스럽다는 확신을 얻었습니다. 오늘의집이 AI Native 조직으로 전환 중인 지금, 제품 문제를 기술로 번역하고 실험과 개선까지 책임지는 Fullstack Product Engineer 역할에 가장 잘 맞다고 생각해 지원했습니다.

2. 멀티테넌트·보안·데이터 모델 최적화로 사용자 경험 개선

의료 도메인 서비스(예진)에서 사용자별 데이터 분리와 권한 관리가 필수였고, UX 데이터를 빠르게 조회해야 하는 요구가 컸습니다. 저는 Amplify 기반 인증/API 자동화 + DynamoDB 모델링 최적화로 멀티테넌트 구조를 구현했습니다. Cognito/Amplify로 테넌트 단위 인증·권한을 구조화하고, DynamoDB 액세스 패턴을 먼저 정의한 뒤 키 설계를 재구성해 조회 비용과 지연을 줄였습니다. 프론트에서는 API 호출 모듈을 정리해 모바일 친화 입력 흐름을 단순화했습니다. 이를 통해 의료진의 실제 업무 흐름에서 입력/조회가 빨라지며 진료 프로세스 시간 단축이라는 명확한 제품 성과를 달성했고, 서비스 안정성과 보안 요구를 모두 충족하는 운영 구조로 정착시켰습니다. 오늘의집 AI Agent 역시 사용자별 맥락/취향 데이터를 다루게 됩니다. 저는 멀티테넌트 사고방식(격리·권한·데이터 경계)을 바탕으로, 개인화된 상담 경험을 안전하게 운영하는 기반을 설계할 수 있습니다.

3. 대규모 시스템을 안정적으로 바꾸는 실행력

실시간 요청과 몇 시간씩 걸리는 배치 작업이 섞여 있는 환경에서 이벤트 기반 비동기 아키텍처를 직접 구축했습니다. DLQ, 재시도 로직, CloudWatch 알림까지 연결해 장애 감지·복구 흐름 자동화하여 7×24 운영이 가능해졌습니다.

유전체 분석 플랫폼에서는 1,000개 이상 샘플을 동시에 처리해야 하는 상황이 왔을 때 기존 단일 EC2 구조에서 AWS Batch 기반 서버리스 + 이벤트 드리븐으로 전환했습니다. 10GB 넘는 참조 데이터를 EFS에 올려 작업 컨테이너들이 공유하게 하고, 샘플 단위로 나누어 병렬 처리하도록 설계했습니다. 병렬 처리 중 EFS I/O 스로틀링 이슈를 겪으며 병목을 식별했고, 다중 EFS 분산/로드밸런싱 개선안을 수립했습니다. 그 결과 처리 시간은 30분에서 10분으로 단축(66%), 월 운영 비용은 600만 원 수준에서 대폭 절감되었습니다. 실시간 요청과 장시간 배치를 분리하고, DLQ·재시도·모니터링을 통해 7×24 운영 안정성을 확보한 경험은 AI Agent 서비스 확장에도 직접적으로 활용할 수 있습니다.

4. AI를 '동료처럼' 쓰는 개발 방식

개인 프로젝트 Specify.app에서는 AWS Bedrock 기반 LLM을 활용해 문맥을 기억하고 사용자의 의도를 추론하는 문서 관리 AI Agent를 구현했습니다. 단일 문서를 처리하는 도구가 아니라, 사용자의 문서를 지속적으로 관리하며 유사 문서 간 연결을 만들고, 축적된 정보로부터 새로운 인사이트를 도출할 수 있는 경험을 하나의 AI-first 제품으로 묶는 것이 목표였습니다. 이를 위해 AI가 단순히 질문에 답하는 역할을 넘어서, 사용자의 의도와 문서 흐름을 따라가며 다음 단계를 제안하고 문서를 함께 발전시켜 나가는 '편집 파트너'가 되도록 설계했습니다.

Next.js + Amplify Gen2/AppSync로 빠른 반복이 가능한 구조를 잡고, Y.js CRDT로 실시간 협업 편집까지 넣었습니다. 충돌 병합이나 지연 누적 이슈는 기능 단위로 잘게 나누어 하나씩 풀었고, LLM은 에이전트 형태로 구성하면서 문맥 유지·의도 추론·편집 이력 반영을 모두 고려했습니다.

개발하면서 LLM을 명세 구체화 → 작업 분해 → 코드 작성·테스트·문서화 전 과정에 자연스럽게 녹여서 생산성을 향상 시켰습니다. 이 방식이 오늘의집이 추구하는 AI Native 개발 문화와 잘 맞는다고 느껴집니다. 특히 오늘의집이 지향하는 "인테리어 의사결정의 복잡함을 상담 경험으로 단순화"라는 목표는, 제가 Specify.app에서 다뤘던 문맥을 지속적으로 유지하며 대화를 통해 사용자의 의도를 구체화하고, 다음 행동으로 자연스럽게 이끄는 흐름 설계와 본질적으로 같은 문제라고 생각합니다.

5. 오늘의집에서

입사 후에는 AI Agent의 핵심 사용자 플로우를 빠르게 실험하고, 상담 → 추천 → 행동(저장·구매)으로 이어지는 경험을 풀스택 관점에서 완성하겠습니다. PO/디자이너/분석가와 함께 문제를 정의하고, 작은 MVP 단위로 실험을 설계해 대화 UX → 추천/요약/분류 → 액션(저장/장바구니/구매)까지 이어지는 흐름을 만들겠습니다. 또한 AI 연산 증가에 대비한 비동기 처리·관측 가능성 강화로, 빠르게 진화하는 서비스 구조에서도 안정적인 제품을 함께 만들어가고 싶습니다. AI 호출/비동기 작업/이벤트 처리 구조를 분리하고 관측 가능성을 강화해, 트래픽과 기능이 빠르게 늘어도 안정적으로 확장 가능한 기반을 만들겠습니다. 제가 해 온 방식처럼 AI를 "코드 생성 도구"가 아니라 개발·테스트·문서화·리뷰까지 포함한 프로세스로 내재화해 팀 전체 효율이 실제로 좋아지도록 기여하겠습니다. 기술로 제품의 방향을 바꾸는 일, 그리고 AI를 동료처럼 활용하는 일은 제가 가장 몰입하는 영역입니다. AI를 통해 오늘의집을 탐색하는 플랫폼에서 상담받는 파트너로 전환하는 여정에 기여하겠습니다.
