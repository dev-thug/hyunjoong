김현중

저는 4년간 스타트업에서 AWS 서버리스·이벤트 기반 아키텍처를 설계/운영하며, AWS Bedrock 기반 LLM Agent를 핵심 워크플로우로 통합한 Specify.app 프로젝트를 통해 AI 기반 서비스 개발 경험을 쌓았습니다. 프롬프트 엔지니어링을 명세 구체화 → 작업 분해 → 코드 작성·테스트·문서화 전 과정에 내재화해 개발 생산성을 70% 이상 향상시켰고, Stateful Context 설계로 LLM의 문맥 유지와 의도 추론을 구현했습니다. 또한 대규모 데이터 처리 파이프라인을 이벤트 드리븐 아키텍처로 전환해 운영 비용을 92% 절감하고 처리 시간을 66% 단축한 경험이 있습니다.

현대오토에버 검색플랫폼개발팀의 "차량 사용자 발화 인지 → 의도 파악 → 서비스 제공" 미션을, 제가 쌓아온 LLM 기반 AI Agent 개발 경험과 프롬프트 엔지니어링 역량으로 즉시 기여하겠습니다.

1. LLM 기반 AI Agent 개발 및 프롬프트 엔지니어링

현대오토에버의 주요업무인 "대규모 언어 모델을 통한 음성인식 서비스 제공"과 "chatGPT 활용을 위한 프롬프트 엔지니어링"에 직접적으로 부합하는 경험을 Specify.app 프로젝트를 통해 쌓았습니다. 이 프로젝트는 Notion의 문서 관리, Cursor IDE의 AI 편집 도구, Obsidian의 지식 연결 구조를 AI-first 경험으로 통합한 협업 문서 편집 솔루션으로, 사용자가 자연어 요구사항을 에이전트 대화를 통해 점진적으로 구체화하면 맞춤형 문서를 자동 생성하도록 설계되었습니다.

  • LLM Agent 아키텍처 설계: AWS Bedrock을 핵심 엔진으로 활용한 LLM 에이전트 시스템을 구현했습니다. Amplify Gen2 기반 백엔드와 AppSync를 통해 실시간 Subscription을 지원하고, Stateful Context 설계로 LLM의 문맥 유지를 보장했습니다. 이는 차량 사용자의 발화를 인지하고 의도를 파악하는 음성인식 서비스의 "발화 → 의도 추론 → 서비스 제공" 플로우와 동일한 구조입니다.
  • 프롬프트 엔지니어링 실전 경험: 단순히 LLM을 호출하는 것이 아니라, 사용자의 의도와 문서 흐름을 따라가며 다음 단계를 제안하는 '편집 파트너'가 되도록 프롬프트를 설계했습니다. 문맥 유지, 사용자 의도 추론, 이전 편집 이력 반영 등 AI Agent 중심 Interaction 설계를 수행했으며, 이를 통해 LLM 응답 품질을 지속적으로 개선했습니다.
  • 개발 프로세스에 AI 내재화: LLM을 명세 구체화 → 작업 분해 → 코드 작성·테스트·문서화 전 과정에 내재화해 개발 생산성을 70% 이상 향상시켰습니다. AI 기반 개발 도구인 Cursor를 전략적으로 활용하여 초기 프로토타입 단계에서 코딩 에이전트를 통해 코드 생성 및 코드리뷰를 진행했고, 명세 기반 개발과 테스트 코드를 통해 에이전트 코딩의 문제를 개선했습니다.

이 경험은 현대오토에버의 "OEM 음성인식 서비스 연동"과 "대규모 언어 모델을 통한 음성인식 서비스 제공" 업무에 직접적으로 적용 가능합니다. 차량 사용자의 발화를 LLM으로 처리하여 의도를 파악하고 적절한 서비스를 제공하는 구조는, 제가 구현한 AI Agent의 "사용자 의도 추론 → 문맥 유지 → 다음 단계 제안" 플로우와 동일한 패턴입니다.

2. 백엔드 서비스 개발 및 시스템 연동

현대오토에버의 "OEM 음성인식 서비스 연동"과 "백엔드 서비스 개발 경험" 요구사항에 부합하는 경험을 유전체 분석 플랫폼과 예진 서비스 프로젝트를 통해 쌓았습니다. 특히 이벤트 드리븐 아키텍처와 외부 서비스 연동 경험은 OEM 서비스와의 통합에 직접적으로 활용할 수 있습니다.

  • 이벤트 드리븐 아키텍처 설계: 유전체 분석 플랫폼에서 EventBridge, SNS/SQS를 활용한 이벤트 기반 비동기 분리 구조를 구현했습니다. "실시간 요청/상태"와 "장기 배치 작업"을 분리해 안정성을 확보했고, 이는 OEM 음성인식 서비스의 "실시간 발화 처리"와 "백그라운드 의도 분석"을 분리하는 구조와 동일합니다.
  • 외부 서비스 연동 경험: 예진 서비스에서 결제 시스템, Jira API 등 외부 서비스와의 연동을 구현했습니다. API 인증, 에러 핸들링, 재시도 정책 등을 체계적으로 설계했고, 이는 OEM 음성인식 서비스와의 연동에도 동일하게 적용 가능합니다.
  • 대규모 병렬 처리 시스템: AWS Batch를 활용해 1,000개 이상의 샘플을 동시에 처리하는 병렬 컴퓨팅 시스템을 설계했습니다. EFS를 활용한 대용량 참조 데이터 (10GB) 공유 최적화와 병렬 처리 확장 시 발생한 I/O 스로틀링 문제를 CloudWatch로 관측하고 개선안을 수립했습니다. 이 경험은 음성인식 서비스의 대규모 동시 요청 처리에 활용할 수 있습니다.
  • 실시간 상태 추적 시스템: AppSync와 GraphQL Subscription을 통해 실시간 상태 추적 시스템을 구현했습니다. SNS/AppSync로 모니터링 체계를 전환하여 사용자에게 실시간 피드백을 제공했고, 이는 차량 사용자의 음성인식 요청 상태를 실시간으로 추적하는 구조와 동일합니다.

이러한 경험을 바탕으로 OEM 음성인식 서비스와의 안정적인 연동 구조를 설계하고, 대규모 트래픽 환경에서도 일관된 성능을 유지하는 백엔드 시스템을 구축하겠습니다.

3. 클라우드 인프라 및 데이터베이스 운영

현대오토에버의 자격요건인 "Python, Linux, DB (Postgresql, Redis, Milvus)"에 부합하는 역량을 AWS 클라우드 환경에서의 운영 경험을 통해 쌓았습니다. TypeScript/Node.js 기반 백엔드 개발 경험은 Python 백엔드 개발로 빠르게 전환 가능하며, AWS 환경에서의 Linux 기반 운영과 다양한 데이터베이스 경험은 요구사항을 충족합니다.

  • 서버리스 아키텍처 설계: Lambda, DynamoDB를 활용한 서버리스 아키텍처를 설계했습니다. 단일 EC2 구조를 AWS Batch 기반 서버리스 아키텍처로 전환해 운영 비용을 92% 절감(600만→50만)하고 처리 시간을 66% 단축(30분→10분)했습니다. DynamoDB NoSQL 모델링 경험은 관계형 DB(Postgresql)와 벡터 DB(Milvus) 이해도로 확장 가능합니다.
  • Linux 기반 컨테이너 환경 운영: AWS Batch와 ECR을 활용한 Linux 기반 컨테이너 환경을 운영했습니다. Docker 컨테이너를 ECR에 저장하고 Batch 작업으로 실행하는 구조를 설계했으며, 이는 Python 기반 백엔드 서비스를 Linux 환경에서 운영하는 것과 동일한 패턴입니다.
  • 데이터베이스 최적화 경험: DynamoDB NoSQL 모델링을 통해 액세스 패턴 중심의 키 설계로 조회 비용과 지연을 감소시켰습니다. 멀티테넌트 구조에서 테넌트 키 중심 논리적 파티셔닝을 적용해 데이터 격리를 구현했고, 이 경험은 Postgresql의 파티셔닝과 Redis의 캐싱 전략 이해로 확장 가능합니다. 또한 LLM Agent의 임베딩 저장 경험은 Milvus 같은 벡터 DB 활용의 기반이 됩니다.
  • IaC 및 자동화: CloudFormation/Terraform 기반 인프라 코드화로 환경 재현과 변경 이력을 관리했습니다. CloudWatch 기반 로그/메트릭 수집 및 알림 연동으로 장애 탐지 시간을 단축했고, 이벤트 기반 비동기 파이프라인에서 DLQ, 재시도 정책을 함께 설계해 장애 전파를 줄였습니다.

Python 백엔드 개발은 TypeScript/Node.js와 유사한 이벤트 드리븐 아키텍처 원리를 바탕으로 빠르게 습득 가능하며, Postgresql/Redis/Milvus는 DynamoDB 운영 경험을 기반으로 체계적으로 학습하겠습니다.

4. 현대오토에버에서의 기여

현대오토에버 검색플랫폼개발팀은 국/내외 자동차의 음성인식과 내비게이션 검색 시스템을 개발 & 운영하는 팀으로, 차량 사용자의 발화를 인지하고 의도를 파악하여 고객들이 원하는 서비스를 제공하는 데 집중하고 있습니다. 저는 이 미션을 "LLM 기반 AI Agent 개발 경험"과 "프롬프트 엔지니어링 역량"으로 즉시 기여하겠습니다.

음성인식 서비스 고도화: Specify.app에서 구현한 LLM Agent의 "사용자 의도 추론 → 문맥 유지 → 다음 단계 제안" 구조를 음성인식 서비스에 적용하겠습니다. 차량 사용자의 발화를 LLM으로 처리하여 의도를 정확히 파악하고, 대화 맥락을 유지하며 적절한 서비스를 제공하는 시스템을 설계하겠습니다. Stateful Context 설계 경험을 바탕으로 대화 흐름을 자연스럽게 유지하는 구조를 구현하겠습니다.

프롬프트 엔지니어링을 통한 서비스 품질 향상: 개발 생산성 70% 향상을 달성한 프롬프트 엔지니어링 경험을 음성인식 서비스의 정확도 향상에 적용하겠습니다. 차량 환경의 노이즈, 방언, 축약어 등 다양한 변수를 고려한 프롬프트 최적화를 통해 음성인식 정확도를 지속적으로 개선하겠습니다.

OEM 서비스 연동 및 안정성 확보: 이벤트 드리븐 아키텍처와 외부 서비스 연동 경험을 바탕으로 OEM 음성인식 서비스와의 안정적인 연동 구조를 설계하겠습니다. 대규모 트래픽 환경에서도 일관된 성능을 유지하는 백엔드 시스템을 구축하고, CloudWatch 기반 모니터링으로 서비스 안정성을 확보하겠습니다.

저는 단순히 기능을 개발하는 것이 아니라, "비용/속도/안정성"으로 증명해 온 방식으로 현대오토에버의 음성인식 서비스 혁신을 함께 만들겠습니다.
