## The value comes after the record

A care log becomes useful when a parent needs to find something again: the last feeding time, a recent sleep pattern, or a developmental item worth checking. Saving the data is only the first step.

Mamma starts with these everyday questions. Quick logs feed into timers, reports, and MammaTalk conversations. I work on planning, design, web and mobile development, and operations as a solo founder.

## Quick input, separate records for each child

Parents can record feeding, sleep, diapers, temperature, medication, bathing, and other care activities. Timers track ongoing sessions, while reports bring together growth measurements and statistics over time.

Each child has a separate profile so records and growth information stay distinct. Developmental checklists are organized around age and can be reviewed alongside previous records.

Community and the play map serve different needs from quick logging. They have their own space for sharing experiences and finding places to visit, rather than interrupting the recording flow.

## How MammaTalk reads care records

An assistant should not make parents explain everything again when the app already holds the relevant records. MammaTalk receives recent records and developmental context for the selected child, with tools available to look up more detail.

The server verifies the user’s access and fixes the child scope before reading records. Notes inside those records are treated as user data, not instructions for the agent.

The current local implementation uses Amazon Bedrock and the Amplify conversation runtime. My focus is on connecting answers to the available context and making the next thing to check understandable.

## One product across web and mobile

The Next.js web app connects to an AWS serverless backend. TanStack Query manages server data, while user and child changes clear the state that should no longer remain on screen.

An Expo native shell hosts the web experience. Device features connect through a bridge, and frequently visited tabs preserve their screens and scroll position. Shared flows remain in the web product, with native capabilities added where needed.
