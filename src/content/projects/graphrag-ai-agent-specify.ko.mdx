## 코드와 문서 사이의 간격을 줄이기

기능은 바뀌었지만 API 가이드와 온보딩 문서는 이전 상태에 머무는 문제에서 출발했습니다. Specify는 개발문서 작성과 변경 검토를 하나의 흐름으로 연결합니다.

## 핵심 흐름

1. GitHub 저장소와 프로젝트 문서를 연결합니다.
2. 개발문서·팀 지식에서 관련 근거를 검색해 초안을 만듭니다.
3. 코드 변경을 읽고 영향을 받는 문서를 찾습니다.
4. 근거와 변경 전후를 비교하며 수정안을 검토합니다.

## 구현에서 중요하게 다룬 경계

문서와 팀 지식은 RAG 검색 대상으로 사용하고, 코드는 저장소에서 직접 읽어 변경 내용을 이해합니다. 문서 생성과 코드 분석의 입력을 구분해 출처를 추적할 수 있도록 구성합니다.

새 프로젝트는 자동 적용 없이 시작하며, 이후 반영은 프로젝트 설정과 정책을 따릅니다. 생성된 문장의 품질과 함께 변경 근거와 검토 가능성을 제품 경험의 중심에 둡니다.

## 적용 대상

API 참조 문서, 연동 가이드, 아키텍처 결정 기록(ADR), 온보딩 문서와 릴리스 노트처럼 코드 변경에 따라 함께 관리해야 하는 문서입니다.
