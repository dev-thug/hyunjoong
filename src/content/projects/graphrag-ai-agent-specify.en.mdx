## Closing the gap between code and documentation

Specify addresses a familiar engineering problem: code changes while API guides and onboarding docs drift behind. The product brings drafting and change review into one workflow.

## Workflow

1. Connect a GitHub repository and project documents.
2. Retrieve team knowledge to ground document drafts.
3. Read code changes and identify affected documents.
4. Review the evidence and proposed differences.

## Engineering focus

Developer documents and team knowledge form the retrieval corpus. Code is read directly from the repository. Keeping these inputs distinct makes the supporting sources easier to inspect.

New projects begin without automatic application. Subsequent updates follow project settings and policy, keeping evidence and review central to the experience.

## Applications

API references, integration guides, architecture decision records, onboarding manuals, and release notes.
