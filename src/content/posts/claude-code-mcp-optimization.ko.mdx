# Claude Code MCP 마스터 가이드: 생산성을 극대화하는 설정과 최적화 팁

지난 포스팅에서는 Claude Code의 기초를 다루었습니다. 오늘은 한 걸음 더 나아가, Claude Code의 핵심인 **MCP(Model Context Protocol)**를 어떻게 하면 더 스마트하고 효율적으로 관리할 수 있는지, 그리고 현업에서 반드시 챙겨야 할 최적화 팁들을 공유하고자 합니다.

---

## 1. 토큰 70% 감소의 비결: Repomix MCP

AI 코딩 에이전트를 사용할 때 가장 큰 병목은 '컨텍스트 윈도우'와 '비용'입니다. **Repomix MCP**는 코드베이스를 AI 친화적인 형식으로 패킹하여 토큰 사용량을 혁신적으로 줄여줍니다.

- **추천 플러그인 조합:**
  ```bash
  /plugin marketplace add repomix/repomix-mcp      # 기본 MCP 서버
  /plugin marketplace add repomix/repomix-commands # 슬래시 명령 지원
  /plugin marketplace add repomix/repomix-explorer # AI 분석 특화 기능
  ```
Tree-sitter 기반의 분석을 통해 불필요한 데이터를 걷어내고 핵심 로직만 전달함으로써 토큰 소모를 최대 70%까지 절감할 수 있습니다.

---

## 2. MCP 관리 핵심 명령어

설치된 MCP 서버들을 효율적으로 관리하기 위한 기본 명령어들입니다.

```bash
# MCP 서버 추가 (사용자 스코프)
claude mcp add [name] --scope user -- [command]

# 설치된 MCP 목록 및 상태 확인
claude mcp list
claude mcp status [name]

# 모든 MCP 서버 최신 상태로 업데이트
claude mcp update --all
```

---

## 3. 프로젝트별 맞춤형 MCP 설정 (Scope 전략)

모든 프로젝트에서 모든 MCP를 로드할 필요는 없습니다. 상황에 맞는 **Scope 전략**이 필요합니다.

| Scope | 사용 범위 | 용도 |
| :--- | :--- | :--- |
| **local** | 현재 프로젝트만 | 특정 프로젝트 전용 도구 (예: 특정 DB 커넥터) |
| **user** | 모든 프로젝트 | 개인적으로 자주 쓰는 공통 도구 (예: GitHub, 메모) |
| **project** | 팀 전체 공유 | 협업용 도구 (버전 관리에 포함 가능) |

**Tip:** 프로젝트 루트에 `.claude/mcp.json`을 생성하면 해당 프로젝트에만 적용되는 MCP를 별도로 관리할 수 있어 전역 설정이 지저분해지는 것을 방지할 수 있습니다.

## 4. 보안과 성능: 환경 변수 및 Lazy Loading

### 보안 관리: 하드코딩 금지 ❌
API 키나 DB 접속 정보를 `mcp.json`에 직접 적지 마세요. 대신 시스템 환경 변수를 활용해야 합니다.

```json
// ✅ 권장 방식: 환경 변수 참조
{
  "env": {
    "API_KEY": "${MY_SERVICE_API_KEY}"
  }
}
```

### 성능 최적화: Heavy Server 관리
성능을 위해 필요할 때만 로드하는 **Lazy Loading** 옵션을 활용하세요. 컨텍스트 사용량을 최대 95%까지 줄여주는 툴 검색 기능을 지원합니다.

## 5. 아키텍트를 위한 추천 MCP 조합 (Specify.app 사례)

제가 개발 중인 **Specify(GraphRAG 기반 AI Agent)**와 같은 복잡한 AWS 인프라 프로젝트를 진행할 때 유용한 조합입니다.

1. **Sequential Thinking**: AI의 논리적 사고 과정을 강화합니다.
2. **GitHub Server**: 이슈 관리 및 코드 리뷰 자동화.
3. **AWS Server**: Amplify, Bedrock 인프라 실시간 관리.
4. **PostgreSQL Server**: 로컬 데이터 스키마 확인 및 테스트.
5. **Context7**: 최신 라이브러리 문서를 실시간으로 참조.

## 6. 마치며: 도구 그 이상의 레버리지

도구를 잘 쓰는 것과 도구를 나에게 맞게 **최적화**하는 것은 큰 차이가 있습니다. MCP 설정을 정교하게 다듬는 과정은 곧 나의 개발 프로세스에서 발생하는 '마찰'을 줄이는 과정입니다.
